# Навык: Создание карточки ПО

## Обзор

Создаёт черновики карточек программного обеспечения для softzor.com.ua. Каждый черновик проходит полный цикл: проверка дублей → исследование → генерация контента → создание в WP → обогащение ACF-полями.

## Пайплайн из 5 шагов

### Шаг 1: Проверка дублей

```bash
curl -s -u "admin:$WP_APP_PASSWORD" \
  "https://softzor.com.ua/wp-json/wp/v2/software?search=$PRODUCT_NAME&lang=ru&page=1"
```

Если в ответе есть записи с тем же базовым именем (часть до ":") — не создавать дубликат. Уведомить anvasan.

### Шаг 2: Исследование продукта

Источники информации (в порядке приоритета):
1. Официальный сайт продукта (`/pricing`, `/features`, `/integrations`, `/about`)
2. Capterra, G2, Trustpilot — отзывы
3. Product Hunt
4. TechRadar, профильные блоги

**Важно:** ВСЕ данные должны быть подкреплены источником. НЕ выдумывать факты.

### Шаг 3: Загрузка справочников

Получить актуальные ID категорий и атрибутов из WP:

```python
# Категории + key_functions
categories = GET https://softzor.com.ua/wp-json/softmir/v1/categories

# Атрибуты ПО  
attributes = GET https://softzor.com.ua/wp-json/softmir/v1/attributes
```

**Критически важно:** Массив `key_functions` у каждой категории — единственный допустимый источник для чекбоксов. Выдумывать значения ЗАПРЕЩЕНО.

### Шаг 4: Подбор метаданных

| Поле | Источник | Обязательность |
|------|----------|----------------|
| `primary_category_id` | Категория продукта | ✅ Всегда |
| `software_categories` | Релевантные категории | ✅ Всегда |
| `category_key_functions` | Из `key_functions` API | ✅ Только из API |
| `origin` | Страна юрлица (UA/US/EU) | ✅ Всегда |
| `vendor_url` | Официальный сайт | ✅ Всегда |

**Обязательные атрибуты (ID):**

| ID | Название | Обязательность |
|----|----------|----------------|
| 425 | Платформа | ✅ Всегда |
| 426 | Язык интерфейса | Желательно |
| 427 | Модель оплаты | ✅ Всегда |
| 428 | Размер бизнеса | ✅ Всегда |
| 430 | Тип установки | ✅ Всегда |
| 1302 | Отрасли бизнеса | ✅ Всегда |

### Шаг 5: Создание черновика и обогащение

```python
# 5a. Создать черновик
POST https://softzor.com.ua/wp-json/wp/v2/software
{
    "title": "Название ПО",
    "status": "draft",
    "lang": "ru"
}
→ Получить post_id

# 5b. Обогащение через enrich-software
POST https://softzor.com.ua/wp-json/softmir/v1/enrich-software
Authorization: Basic base64("admin:$APP_PASSWORD")
Content-Type: application/json
{
    "ID": post_id,
    "title": "...",
    "short_description": "...",
    "full_description": "<HTML со всеми 6 блоками>",
    "price_summary": "...",
    "advantages": [...],
    "disadvantages": [...],
    "best_for": [...],
    "bad_for": [...],
    "scenarios": [...],
    "features": [...],
    "integrations": [...],
    "primary_category_id": NNN,
    "software_categories": [NNN, NNN],
    "category_key_functions": [...],
    "attributes": [...],
    "origin": "UA",
    "verdict": "...",
    "pricing_list": [...],
    "external_reviews": [...]
}
```

## 6 обязательных HTML-блоков full_description

Каждый блок ОБЯЗАТЕЛЕН, пропуск запрещён:

```html
<!-- БЛОК 1 -->
<p>🟢 <b>Релевантность: [85-99]%</b><br>
<b>Почему SoftZor рекомендует:</b> [3-4 предложения. Детально — суть + главная боль. Без слов бан-листа.]</p>

<!-- БЛОК 2 -->
<h3>⚖️ Экспертный вердикт SoftZor</h3>
<p><b>Кому брать:</b> [чёткий профиль].</p>
<p><b>Кому обходить стороной:</b> [кому точно не подойдёт].</p>
<p><b>⚡ Порог входа:</b> [скорость внедрения + сложность обучения].</p>
<blockquote><b>💡 Совет практика:</b> [при каких условиях внедрять].</blockquote>

<!-- БЛОК 3 -->
<h3>⚙️ Главные функции</h3>
<table>
<tr><th>Функция</th><th>Как решает боль</th><th>Для кого</th></tr>
<tr><td>...</td><td>...</td><td>...</td></tr>
</table>

<!-- БЛОК 4 -->
<h3>🔄 Главные конкуренты (Аналоги)</h3>
<ul>
<li><b>[Название]</b> — [1 предложение对比] (ссылка на реальную карточку softzor.com.ua)</li>
</ul>
ПРИОРИТЕТ: программы с партнёрскими ссылками.

<!-- БЛОК 5 -->
<h3>🗣️ Что говорят реальные пользователи</h3>
<p>Обобщение отзывов с источников.</p>
<blockquote>"[Прямая цитата позитивная]", — [Имя/компания], [Источник]</blockquote>
<blockquote>"[Прямая цитата критическая]", — [Имя/компания], [Источник]</blockquote>
МИНИМУМ 2 отзыва: 1 позитивный + 1 с критикой.

<!-- БЛОК 6 -->
<h3>💰 Цены и тарифы</h3>
<p>Реальные данные с /pricing. Дисклеймер с датой проверки.</p>
<p><i>Цены актуальны на [YYYY-MM-DD]. Проверяйте на официальном сайте.</i></p>
```

## Правила по полям

### advantages (плюсы)
- Макс 7 пунктов, 10-18 слов каждый
- Только технические факты, без прилагательных без фактов
- Цифра всегда с контекстом: "доставляемость 97% (норма 95%+)"
- Минимум 3 (иначе выглядит как реклама)

### disadvantages (минусы)
- Макс 7 пунктов, 10-18 слов
- МИНИМУМ 3 реальных недостатка (иначе карточка выглядит рекламой)
- Ситуативные, не фатальные: "сложно для новичков", не "зависает"
- Запрещено: "Нет информации о...", "Отсутствие упоминания о..."
- НЕ дублировать с bad_for

### best_for (кому подходит)
- Макс 5 пунктов, 10-18 слов

### bad_for (кому не подходит)
- Макс 5 пунктов, 10-18 слов
- МИНИМУМ 2 пункта — обязательно
- Профиль бизнеса + причина несовпадения (не техлимиты!)

### scenarios (сценарии)
- РОВНО 3 сценария (не "макс 3")
- Формат: `{"title": "Название", "desc": "Боль → Как спасает"}`
- Про людей и эмоции. ✅ "Менеджер путается во вкладках → всё в одном окне"

### pricing_list / price_summary
- Цены ТОЛЬКО с официальной страницы /pricing
- Если не нашёл явно → "Цена по запросу" + ссылка
- ЗАПРЕЩЕНО угадывать или интерполировать
- Заполнять `price_updated_date` датой проверки

### external_reviews
- МИНИМУМ 2: 1 позитивный + 1 с критикой
- Только прямые цитаты с переводом
- Источник обязателен: Capterra/G2 + рейтинг

### SEO (rank_math_title)
- Максимум 55 символов
- Обязательно: название + ключевой запрос + выгода
- Синтаксис свободный (НЕ жёсткий шаблон)
- Запрещено: "Цены", "2024", "Отзывы" в заголовках

## Критические запреты

1. **НЕ выдумывай** `category_key_functions` — только из API
2. **НЕ пропускай** блоки в `full_description` — все 6 обязательны
3. **НЕ дублируй** `short_description` и блок «Почему рекомендует»
4. **НЕ пиши** прилагательные без фактов в advantages
5. **НЕ добавляй** сценарии в full_description — они в поле scenarios
6. **МИНИМУМ 3** disadvantages (иначе = реклама)
7. **НЕ забывай** атрибуты 427 (оплата) и 1302 (отрасли)

## Чеклист перед отправкой

- [ ] `full_description` содержит 6 секций с `<h3>` (кроме первого блока)
- [ ] В блоке ⚙️ есть `<table>` с минимум 3 строками
- [ ] В блоке 🗣️ есть минимум 2 `<blockquote>` с цитатами
- [ ] `category_key_functions` — строки только из `key_functions` категории
- [ ] `attributes` содержит ID 425, 427, 430, 1302
- [ ] `disadvantages` ≥ 3 пунктов
- [ ] `scenarios` = ровно 3 сценария
